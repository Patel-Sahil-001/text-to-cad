Cloud Deployment & Database Architecture

Do I Need a Database for Past Files & Parts?

Short answer: No for local/Render disk, but an Object Store (S3/R2) is best for serverless cloud scale.

  • How it works currently: The dashboard automatically organizes every part in dashboard/projects/<project_id>/ storing meta.json, model.py, model.step, and model.stl. Zero setup required!
  • On Render: Attach a Render Persistent Disk at /app/dashboard/projects ($1/month for 1GB). Your files persist forever across redeploys without needing any SQL database.
  • For High Scale / Multi-User: You store binary 3D files (.stl, .step) in Cloudflare R2 or AWS S3 (free/cheap object storage) and save part metadata/prompts in SQLite / Supabase / PostgreSQL.

Option A: Deploy to Render (Recommended for full CAD Compiler)

Render runs the complete Python & OpenCASCADE CAD compiler container seamlessly using the provided Dockerfile and render.yaml.

  1. Push this repository to your GitHub account (Patel-Sahil-001/text-to-cad).
  2. Go to dashboard.render.com → New + → Web Service.
  3. Connect your repository. Render will automatically detect Dockerfile.
  4. Under Environment Variables, add:
    GROQ_API_KEY = (your groq key)
    GROQ_MODEL = openai/gpt-oss-120b
  5. Click Deploy Web Service. Done!

Option B: Deploy to Vercel

Vercel can host the static frontend dashboard and connect to your Render backend API.

  1. Import this repository at vercel.com/new.
  2. The included vercel.json serves the static dashboard at dashboard/static.
